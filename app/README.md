# 练界 · 训练记录（最小版）

原生微信小程序。只做两件事：**记录今天的训练** + **看自己练了多少**。

---

## 怎么跑起来

1. 打开 **微信开发者工具** → 导入项目
2. 目录选 `E:\wx小程序\app`
3. AppID 选 **「测试号」**（或点「无 AppID」），不用真 AppID 也能跑
4. 编译

> `project.config.json` 里的 appid 现在是 `touristappid`（游客模式）。有自己小程序的话把它换成你的 AppID。

第一次启动会自动写入：8 个动作、一周计划（周一/三/五）、以及一份示例记录 —— 这样「数据」页不是空的。

---

## 三个页面

| 页面 | 路径 | 作用 |
|---|---|---|
| 今天练什么 | `pages/today/index` | 显示今天的计划与动作清单，点「开始训练」 |
| 记录 | `pages/record/index` | 一组组勾选，记重量次数，90 秒休息倒计时 |
| 数据 | `pages/stats/index` | 本月天数 / 本周进度 / 累计吨数 / 日历 / 部位分布 / 动作频次 |

`record` 不在 tabBar 里，是从 today 用 `navigateTo` 打开的。

## 数据存在哪

**第一版全部用微信本地存储（wx.setStorageSync）**，键：

| 键 | 内容 |
|---|---|
| `lj.exercises` | 动作字典 |
| `lj.plans` | 一周计划 |
| `lj.sets` | 所有组记录（唯一的真实数据） |
| `lj.seeded` | 是否已初始化 |

组记录的结构：

```js
{
  id: '2026-10-28-e1-0',   // 日期-动作-组号，天然去重
  date: '2026-10-28',
  exId: 'e1', exCn: '高脚杯深蹲', part: 'legs',
  setNo: 1,
  weight: 24, reps: 12, unit: 'kg',
  done: true
}
```

**注意**：同一天同一动作同一组号再存会**覆盖**，不会重复（`saveSet` 里按 id 查找）。

清空重来：在开发者工具控制台执行
```js
wx.clearStorageSync()
```

## 两个已经踩过的坑（别改回去）

1. **「连续天数」对隔天计划没意义**
   计划是周一/三/五，连续天数永远只有 1。所以指标改成了「本周 X/3」。如果以后做成每天都练的计划，再考虑加回来。

2. **部位分布按「组数」算，不按「容量」**
   按容量的话，腿因为重量大（24kg×12 组 vs 引体 0kg），会被放大到 79%，看起来像只有腿在练。按组数看是 44% / 18% / 17% / 16% / 5%，更像真实情况。
