# 练界 · 训练记录小程序

一个微信小程序：**记录今天的训练，看见自己的进步。**

只做两件事——训练记录、数据可视化。功能刻意保持克制，先把基础做扎实。

## 现在有什么

| 页面 | 能做什么 |
|---|---|
| 今天练什么 | 按星期显示今天的计划（一/三/五分别下肢、上肢、全身），列出动作与组次；休息日给提示 |
| 记录 | 一组组勾选完成，90 秒休息倒计时，显示该动作上次的记录 |
| 数据 | 本月训练天数、本周进度、累计吨数、月历热力图、部位分布、动作频次 TOP5 |

数据全部存在**微信本地存储**，不需要后端。

## 设计上的几个决定

**为什么不做「连续天数」**
训练计划是隔天（一/三/五），连续天数永远只有 1，这个指标没有意义。改成「本周 X/3」。

**为什么部位分布按「组数」而不是「容量」**
按容量算，腿（24kg×12）会把自重动作（引体 0kg）压到看不见，腿会占到 79%。按组数算才是 44/18/17/16/5，接近真实。

**为什么数据层单独一个文件**
以后换云开发只改 `utils/db.js`，页面不动。

一次推到两边：

```bash
git push gitee main && git push github main
```

> GitHub 走的是 ssh 443，不是默认的 22 端口——因为本机直连 github.com 的 22 端口不通。

## 协作

多人开发前先看 **[CONTRIBUTING.md](CONTRIBUTING.md)**（分支怎么开、commit 怎么写、PR 流程、冲突处理、这个项目的硬约定）。

已配置：

- `.gitattributes` 统一换行符为 LF，避免 Windows/macOS 互相制造假冲突
- `.github/pull_request_template.md` 和 `.gitee/PULL_REQUEST_TEMPLATE.md` 提 PR 时自动带清单
- `project.private.config.json` 已排除（每人的微信开发者工具配置不同）

**`main` 分支建议开保护**：Gitee 在「管理 → 保护分支」，GitHub 在「Settings → Branches」，勾选禁止直接推送。
