# 练界 · 训练记录小程序

一个微信小程序：**记录今天的训练，看见自己的进步。**

只做两件事——训练记录、数据可视化。功能刻意保持克制，先把基础做扎实。

## 现在有什么

| 页面 | 能做什么 |
|---|---|
| 欢迎 | 第一次进入：品牌 → 选水平 → 选频率与场所 → 生成你的训练日 |
| 今天练什么 | 本周进度（2/3）、今天该练哪个训练日、今日完成几个动作；练完自动排下一个，跨周连续不丢训练日；点动作可直达 |
| 记录 | 大杠铃累积（片数=重量、点亮=进度、PR 那片陶土色）、超大重量数字、组进度点、目标/容量/上次/动作要点四行、组记录可改数字、组间呼吸环 |
| 今日战报 | 练完的收尾页：组数 / 吨数 / 破纪录 / 部位分布 |
| 数据 | 本月训练天数、本周进度、累计吨数、月历热力图、部位分布、动作频次 TOP5 |
| 我的 | 当前计划、一周几次 / 在哪练 / 水平、示例数据与清空；入口到「方案」 |
| 方案 | **6 套官方预排方案**（居家 3 / 健身房 3）+ 一键启用、展开看每天练什么、退回按参数自动排 |
| 自己搭 | 从 105 个动作里逐天挑：定场所/水平/训练日数，按部位筛动作，一天最多 8 个 |

数据全部存在**微信本地存储**，不需要后端。

### 动作库与方案

- **105 个动作**（健身房 52 / 居家 53），按 `part × place` 铺开，每个格子至少 6 个，「换一个」才换得出来
- **6 套官方方案**写在 `data/programs.js`：全身入门（居家 2 练）、居家塑形、核心与体态、器械入门、增肌推拉腿、上下肢四练
- **自定义方案**用同一种结构存（`lj.customPrograms`），启用时和官方方案走同一条路径：展开成 `lj.plans` 的训练日队列
- 所以**今天 / 记录 / 战报 / 数据四个页面对「方案」一无所知**，它们只认训练日队列

换方案会改 `planSig`，旧方案下的记录不再参与轮转，但训练记录本身一条不删。

### 首次进入流程

```
打开小程序
  └→ 欢迎页（品牌 + 一句话）
      └→ 你练了多久？（刚开始 / 练过一阵 / 一直在练）
          └→ 一周几次？（2 / 3 / 4）· 在哪练？（健身房 / 家里）
              └→ 生成周计划 → 落到「今天练什么」
```

- **水平**决定组数和起始重量（新手的卧推 30kg，练过的 50kg）
- **频率**决定一周排几天（2 练全身 A/B、3 练推/拉/腿、4 练上/下）
- **场所**决定用哪套动作（健身房 14 个 / 居家 11 个，居家全自重）
- 走完一次就不再出现

**首页不会再看到别人的假数据。** 只有用户主动点「先看看示例数据」时，才会按他自己的计划造一份演示记录。

## 设计上的几个决定

**计划是「训练日排队」，不是「课表」**

```
不是：周一练推日、周三练拉日、周五练腿日
而是：本周目标 3 次 → A 推日 / B 拉日 / C 腿日 排队

今天该练什么 = 本周还没练的下一个
周一没练 → 周二还是 A（自动顺延，不用手动补）
本周练满 3 次 → 显示「本周已完成」，仍可以加练
下周一 → 从 A 重新开始
```

原因是真实的人想「我这周练三次」，不是「我必须在周一练推」。跳过一天就乱套的课表，用起来一直有负担。

**重量会自己往上走**

每个动作记着上次的成绩：

- 上次所有组次数都做满 → 今天 +2.5kg（下肢 +5kg，取到 2.5 的整数倍）
- 上次没做满 → 保持原重量

这个值预填在记录页，不想听建议直接改就行。健身的核心是渐进超负荷，App 不参与这个决策就只是个记事本。

**为什么不做「连续天数」**
训练计划是隔天（一/三/五），连续天数永远只有 1，这个指标没有意义。改成「本周 X/3」。

**为什么部位分布按「组数」而不是「容量」**
按容量算，腿（24kg×12）会把自重动作（引体 0kg）压到看不见，腿会占到 79%。按组数算才是 44/18/17/16/5，接近真实。

**为什么数据层单独一个文件**
以后换云开发只改 `utils/db.js`，页面不动。
