## 1. 先看这个：页面不调后端接口

```
┌─────────────── 小程序 ───────────────┐
│  页面（pages/*）        ← 页面开发负责  │
│     │ 只调用 db.xxx()，同步返回         │
│     ▼                                 │
│  数据层（utils/db.js 等）← 后端侧负责   │
│     │ 读写手机本地存储                  │
│     ▼                                 │
│  sync.js（后台自动同步）← 后端侧负责    │
└─────┼─────────────────────────────────┘
      │ POST /api/sync（唯一的网络请求）
      ▼
   Go 后端 + PostgreSQL                 ← 后端侧负责
```

| 角色 | 负责 | 不需要关心 |
|---|---|---|
| **页面开发** | `pages/` `components/`：界面、交互、调用 `db.*` | 网络请求、登录、token、同步、重试、离线 |
| **后端侧** | `utils/db.js` `utils/storage.js` `utils/sync.js`、`server/` | 界面 |

**为什么这样分**：健身房常常没信号，「完成这组」不能等网络。所以页面永远只读写本地，`db.*` 全部是**同步函数**，立刻返回；数据什么时候传到服务器、传失败怎么重试，由 `sync.js` 在后台处理。

对页面开发的直接好处：

- **不需要后端就能开发和调试全部功能**（§2.1）
- 不用写任何 `wx.request`、loading、网络错误处理
- 断网、后端挂掉，页面行为完全不变

## 2. 怎么开发和调试

### 2.1 日常开发：纯本地模式（推荐，不需要后端）

| 步骤 | 做法 |
|---|---|
| 1 | 微信开发者工具导入 `app/` 目录，AppID 用测试号 |
| 2 | `app/utils/config.js` 里 `develop` 的地址**留空**（= 不同步，纯本地）。默认就是空的，什么都不用配 |
| 3 | 正常开发页面，调用 `db.*` |

数据怎么看、怎么造：

| 需求 | 做法 |
|---|---|
| 看存了什么 | 开发者工具 → 调试器 → **Storage** 面板，键名都以 `lj.` 开头（§6） |
| 在控制台直接调 | `require('./utils/db.js')` 后调用任意方法，例：`db.todayWorkout()` |
| 造一批历史数据 | 「我的」页 →「先看看示例数据」（或控制台 `db.loadDemo()`） |
| 回到全新用户 | 「我的」页 →「重新引导」（或控制台 `db.resetAll()`），或清除缓存 |
| 测跨零点、昨天的训练 | 方法都接受可选的 `date` 参数，传 `'2026-10-30'` 即可，不用改系统时间 |

### 2.2 联调同步：连本机后端

只有要验证「换设备能拉回来」这类同步行为时才需要。

```bash
cd server
cp .env.example .env          # DEV_MODE=true：登录不调微信
docker compose up -d          # 起 Postgres + Go 后端，监听 :8080
curl http://localhost:8080/api/healthz
```

| 步骤 | 做法 |
|---|---|
| 1 | `config.js` 的 `develop` 填 `http://localhost:8080` |
| 2 | 开发者工具 → 详情 → 本地设置 → 勾选「**不校验合法域名**」 |
| 3 | 重新编译。`sync.js` 会自动登录（DEV_MODE 下不调微信）并开始同步 |
| 4 | 模拟第二台设备：开发者工具清缓存后重新编译 = 一台新手机，应该能拉回刚才的记录 |

看服务器上的数据：

```bash
docker compose exec db psql -U lianjie -d lianjie \
  -c "select date, ex_cn, set_no, weight, reps, warmup, done from sets order by date desc, completed_at limit 20;"
```

同步状态（待上传几条、上次同步时间、最近一次错误）：控制台 `require('./utils/sync.js').status()`（随 `sync.js` 一起提供，见 §8）。

> 在 `sync.js` 完成之前，2.2 只能用来验证后端本身（`curl` 调 `/api/sync`），小程序还不会发起同步。

## 3. 数据结构

页面拿到的都是**普通对象**，只读；要改数据，调用 §4 的方法，不要直接改对象再存回去。

### 3.1 `SetItem`：一组

```js
{
  setNo: 2,                 // 组号，从 1 起；取消过的组会留空号，不要求连续
  weight: 16,               // 负重动作是重量；自重 / 计时为 0
  reps: 10,                 // 次数；计时动作是秒数
  unit: 'kg',               // kg | bw | sec
  warmup: false,            // 热身组
  done: true,               // 已完成。数据层返回的组都是 done=true；未完成的组只存在页面里
  completedAt: '2026-10-31T11:05:12.120Z',
  pr: false                 // 这一组是否破纪录（只看正式组、负重动作）
}
```

### 3.2 `ExerciseBlock`：今天的一个动作

```js
{
  exId: 'g23',
  cn: '上斜哑铃卧推', en: 'Incline DB Press',
  part: 'chest', partCn: '胸',
  unit: 'kg',
  tips: '靠背约 30°，哑铃落到胸上沿',
  source: 'plan',           // plan = 来自计划推荐；manual = 自己选的
  slot: 0,                  // 来自计划时的位置；manual 为 null
  plan: { sets: 4, reps: 10, weight: 16 },   // 计划目标；manual 为 null
  sets: [ /* SetItem，按组号升序 */ ],
  firstAt: '2026-10-31T11:02:15.120Z',       // 第一组完成时刻；还没练为 null
  status: 'doing'           // todo（没练）| doing（练了，但少于计划组数）| done（达到计划组数；manual 有组即 done）
}
```

### 3.3 `WorkoutView`：今天的训练全貌

```js
{
  date: '2026-10-31',
  mode: 'plan',             // plan = 有计划；free = 没有计划，自由训练
  plan: { key: 'B', name: '拉日', en: 'Pull' },   // free 时为 null
  status: 'active',         // idle（今天还没练）| active（练了，没点完成）| finished（点了完成训练）
  startedAt: '…', finishedAt: null,
  minutes: 34,              // 训练时长，算不出为 null

  exercises: [ /* ExerciseBlock */ ],
  // 排序：已练的按 firstAt 升序在前；没练的计划推荐在后，保持计划顺序

  current: 'g23',           // 建议的「当前动作」（模块设计 §5.2）；没有可练的为 null（free 且今天没练）
  totals: { sets: 7, exercises: 2, ton: 1.2 },    // 只算正式组；吨数只算负重
  week: { done: 1, target: 3, finished: false }
}
```

### 3.4 `Prefill`：选中一个动作时的预填

```js
{
  exId: 'g23',
  weight: 16, reps: 10,     // 新的一组预填这两个数
  sets: 4,                  // 建议组数（计划动作 = 计划组数；manual = 上次组数，没有则 3）
  reason: 'up',             // first（第一次做）| up（建议加重）| keep（保持）| hint（自选动作：可以试试加，但没自动加）
  step: 2.5,                // 建议加的重量；不加为 0
  lastText: '上次 16 kg × 10 × 3 组',
  hintText: '全部完成，今天加 2.5 kg',   // 没有提示为 ''
  nextSetNo: 3,             // 今天这个动作下一组的组号（今天已练过时 > 1）
  todaySets: [ /* 今天已完成的 SetItem */ ],
  maxBefore: 17.5           // 今天之前的最大重量（页面判断「这组会不会破纪录」用）；没练过为 0
}
```

### 3.5 `PickList`：选动作面板

```js
{
  recommended: [            // 计划里今天还没练的动作，保持计划顺序；free 时为 []
    { exId: 'g6', cn: '俯身划船', part: 'back', partCn: '背', unit: 'kg', slot: 1, doneToday: false }
  ],
  groups: [                 // 动作库，按部位分组
    { part: 'chest', partCn: '胸', items: [
      { exId: 'g1', cn: '卧推', en: 'Bench Press', unit: 'kg', place: 'gym', doneToday: true, recent: true }
    ]}
  ]
}
```

`recent: true` = 最近 4 周练过，方便页面排在前面或打标。

## 4. 方法

状态说明：**现有** = 原来就有；**新增 / 修改** = 本期新做。**全部已实现可用**（见 §8）。所有方法都是同步的，不会抛网络错误。

### 4.1 读

| 方法 | 状态 | 返回 | 用在 |
|---|---|---|---|
| `db.trainingDate()` | 新增 | `'2026-10-31'`：当前应该记在哪一天（含跨零点规则，模块设计 §6.5） | 页面 `onLoad` 时取一次，整页沿用 |
| `db.todayWorkout(date?)` | 新增 | `WorkoutView` | today 页、record 页 |
| `db.exercisePrefill(exId, date?)` | 新增 | `Prefill` | 选中 / 切换到一个动作时 |
| `db.pickableExercises({ date?, place?, part?, keyword? })` | 新增 | `PickList`。`place` 默认用户设置的场所，传 `'all'` 不过滤 | 选动作面板 |
| `db.alternatives(exId, planKey?)` | 修改 | 换动作候选 `[{ id, cn, part, unit }]`，排除当天已有和已练的动作 | 「换动作」 |
| `db.todayReport(date?)` | 修改 | 战报数据，新增 `minutes`（训练时长，算不出为 `null`）、`blocks`（`ExerciseBlock[]`，按完成先后）。原有的 `exercises` 仍是动作个数 | report 页 |
| `db.nextSetNo(exId, date?)` | 新增 | 这个动作今天下一组的组号（`Prefill.nextSetNo` 同值） | |
| `db.workout(date?)` | 新增 | 某天的「一次训练」：`{ date, planKey, planName, startedAt, finishedAt, … }`；没有为 `null` | |
| `db.exerciseById(id)` | 现有 | 动作库里的一条 | |
| `db.profile()` `db.profileText()` | 现有 | 设置、设置的一行描述 | |

### 4.2 写

| 方法 | 状态 | 说明 |
|---|---|---|
| `db.saveSet(rec)` | 修改 | 完成一组，或修改已完成组的数字 / 热身标记。见下 |
| `db.uncheckSet({ date, exId, setNo })` | 新增 | 取消一组。页面上这组变回未完成 |
| `db.finishWorkout(date?)` | 新增 | 点「完成训练」时调用。今天一组都没有时返回 `false`，页面提示「还没记录任何一组」 |
| `db.setSwap(planKey, slot, exId)` | 现有 | 换动作（永久替换计划里的位置） |

`saveSet` 的参数：

```js
db.saveSet({
  date: '2026-10-31',       // 必填，用 trainingDate() 的值
  exId: 'g23',              // 必填
  setNo: 3,                 // 必填，新的一组用 Prefill.nextSetNo 往后数
  weight: 16, reps: 10,     // 必填
  unit: 'kg',               // 必填，取动作的 unit
  warmup: false,            // 可选，默认 false
  slot: 0,                  // 来自计划时必传；自己选的不传
  targetWeight: 16, targetReps: 10, targetSets: 4   // 来自计划时传 plan；自己选的传 Prefill 的 weight / reps
})
// 返回保存后的 SetItem
```

- 同一个 `(date, exId, setNo)` 再调一次 = **修改**这一组。`completedAt` 只在第一次完成时写，改数字不变
- `exCn`、`part`、`planKey`、计划签名等由数据层自己补，页面不用传
- 当天第一组时，数据层自动创建「一次训练」

### 4.3 事件：数据变了要刷新

```js
const store = require('../../store/index');

onLoad() { this.onChange = () => this.refresh(); store.on(this.onChange); }
onUnload() { store.off(this.onChange); }
```

| 什么时候触发 | 回调参数 |
|---|---|
| 调用了 `saveSet` / `uncheckSet` / `finishWorkout` / `clearSets` / `loadDemo`（数据层自动触发，页面不用再调 `store.touchSets()`） | `('setsVersion', n)` |
| 后台同步从服务器拉到了别的设备的改动 | `('setsVersion', n)`（同一个事件，页面不用区分来源） |

today、stats 这类展示页**必须**监听，否则另一台设备的记录同步过来后页面不会变。

## 5. 典型流程（伪代码）

### 5.1 today 页

```js
onShow() {
  const date = db.trainingDate();
  const w = db.todayWorkout(date);
  // w.mode === 'free' → 标题「今天自由训练」
  // w.exercises → 列表：已练的在前（带组数），没练的推荐在后
  // 主按钮：w.status === 'idle' ? '开始训练' : '继续训练'；w.status === 'finished' 时可加「看战报」
}
openEx(e)  { wx.navigateTo({ url: '/pages/record/index?ex=' + e.currentTarget.dataset.ex }); }
start()    { wx.navigateTo({ url: '/pages/record/index' }); }
```

### 5.2 record 页

```js
onLoad(q) {
  this.date = db.trainingDate();                      // 整页固定这一天
  const w = db.todayWorkout(this.date);
  const exId = q.ex || w.current;
  exId ? this.useExercise(exId) : this.openPicker();  // free 且今天没练 → 直接选动作
}

useExercise(exId) {                                   // 选中 / 切换到一个动作
  const pre = db.exercisePrefill(exId, this.date);
  const block = db.todayWorkout(this.date).exercises.find(x => x.exId === exId);
  // 页面上的组 = 今天已完成的 pre.todaySets + 若干未完成组（数量 = pre.sets - 已完成数，至少 1 组）
  // 未完成组预填 pre.weight / pre.reps；组号从 pre.nextSetNo 往后
  // 记下 block?.source / slot / plan，保存时要用
}

completeSet(row) {
  db.saveSet({ date: this.date, exId, setNo: row.setNo, weight: row.weight, reps: row.reps,
               unit, warmup: row.warmup, slot, targetWeight, targetReps, targetSets });
  // 开始 90 秒休息
}
uncheck(row)     { db.uncheckSet({ date: this.date, exId, setNo: row.setNo }); }
editDone(row)    { db.saveSet({ /* 同上，带新数字 */ }); }   // 已完成组改数字 / 热身
addSet()         { /* 只加在页面上：复制最后一组，setNo = 当前最大组号 + 1 */ }

openPicker()     { const list = db.pickableExercises({ date: this.date }); /* 显示面板 */ }
onPick(exId)     { this.useExercise(exId); }

finish() {
  if (!db.finishWorkout(this.date)) return wx.showToast({ title: '还没记录任何一组', icon: 'none' });
  wx.redirectTo({ url: '/pages/report/index?date=' + this.date });
}
```

要点：

- **未完成的组只存在页面里**，不调任何方法；完成时才 `saveSet`
- 「当前动作」也只是页面状态。选了动作一组没做就离开，什么都不会留下
- 组数不限：「加一组」不要设上限（服务端上限 50，正常训练碰不到）

## 6. 本地存储键（只读参考）

页面**不要直接读写**这些键，只在 Storage 面板里看。

## 7. 页面不需要处理的事

| 事 | 谁处理 |
|---|---|
| 登录、token 过期 | `sync.js` 静默完成 |
| 网络失败、重试 | `sync.js` 退避重试，页面无感知 |
| 两台设备改了同一组 | 服务端按规则合并，结果通过 §4.3 的事件推给页面 |
| 存储容量 | 数据层按月分片 |
| 示例数据会不会被上传 | 数据层标记，永不上传 |
