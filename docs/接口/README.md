# 接口文档

> 本目录回答「**调什么、返回什么**」。回答「**为什么这么做**」的在 [`../设计文档/`](../设计文档/README.md)。
> 页面开发只需要看这个目录。

| 文档 | 内容 | 状态 |
|---|---|---|
| [`HTTP契约.md`](./HTTP契约.md) | 前后端唯一的 HTTP 约定：端点、字段、同步语义、校验、错误码 | v3.2，与代码一致 |
| [`训练记录.md`](./训练记录.md) | 训练记录模块的客户端数据层函数（`todayWorkout` / `saveSet` …） | v0.2，已实现 |
| 动作库.md | 动作库模块的客户端数据层函数（`catalog.*` / `saveCustomExercise` …） | 待写（随 E2 一起） |

没实现的模块**不写接口文档**——写了没人用，还很快过时。

---

## 1. 三层，各写各的，不重复

| 层 | 写在哪 | 只写什么 |
|---|---|---|
| HTTP | **只在** [`HTTP契约.md`](./HTTP契约.md) | 端点、鉴权、限流、错误码、同步协议语义 |
| 客户端数据层 | 本目录，每模块一份 | 函数签名、返回结构、副作用、状态 |
| 表结构 | 模块设计文档 §数据模型 | 表、列、约束 |

**同一个事实只在一处写，别处放链接。** 模块接口文档里提到端点时，写端点名 + 链接，不要复述字段。

## 2. 每份模块接口文档的固定结构

1. **页面能调什么** —— 一句话 + 总表（函数名 / 作用 / 状态）
2. **函数签名与返回值** —— 逐个，含返回结构示例
3. **写操作的副作用** —— 触发哪些事件、标脏、缓存失效
4. **与其他模块的交界** —— 谁调我、我调谁（防循环依赖）
5. **状态** —— 已实现 / 待实现（待实现的签名同样冻结）
6. **调试** —— 不开后端怎么跑（假数据开关）
7. **变更记录**

## 3. 冻结规则

**签名冻结的文档可以先写页面。** 标「待实现」的方法，名字、参数、返回结构一旦写进文档就视为契约，实现方不能改签名（要改先改文档并在 PR 里说明）。

这条来自本项目的实践经验：`训练记录.md` 的 v0.1 就把待实现的方法签名冻结了，页面确实是按它先写完的，数据层后来照着文档实现，一次没返工。

## 4. 状态只有三种

| 状态 | 含义 |
|---|---|
| 已实现 | 代码里有，测试覆盖了 |
| 待实现 | 签名已冻结，代码还没有 |
| 已废弃 | 保留说明，标注替代品和删除版本 |

**不允许写「大概是这样」。** 不确定的参数就是不冻结，先不写。

## 5. 维护规则

| 什么时候 | 改什么 |
|---|---|
| 加 / 改 / 删一个数据层函数 | 必须同时改对应模块的接口文档（PR 模板有勾选项） |
| 改 HTTP 端点或字段 | 必须同时改 `HTTP契约.md`（模块文档不重复字段） |
| 验收 / 交付标准 | 不改这里，改 `设计文档/*-后端验收.md` |
| 改表结构 | 不改这里，改 `设计文档/<模块>.md` §数据模型 |

**漂移检测**（计划）：`node scripts/check-api-docs.js` 比对 `app/utils/db.js` 的 `module.exports` 与本目录表格里的函数名，报「文档有代码无 / 代码有文档无 / 参数不一致」。
