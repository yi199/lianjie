## 1. 目标

1. **记录不丢**：换设备能拉回来，断网也能记

## 5. 验收标准

### P1 后端

**15 个集成测试 + 15 个单元测试，全部通过**（真 Postgres）。核心场景：

| 场景 | 期望 | 用例 |
|---|---|---|
| 同一组重复上传 3 次 | 服务端只有 1 行 | `IdempotentRetry` |
| 上传的行赢了 LWW | 响应里不回传这行（去回声） | `EchoSkipped` |
| 上传比服务端旧的行 | 不覆盖；响应里回传服务端赢家 | `LWW` |
| 时钟慢很多的设备写入 | 其他设备按游标一定拉得到 | `ClockSkewNotMissed` |
| 取消勾选（墓碑） | 其他设备收到墓碑；统计不再计入 | `Tombstone` |
| 新设备拉取 1234 行 | 分页拉全，不多不少 | `Pagination` |
| 一批里混有坏行 | 坏行进 `rejected`，好行照常写入 | `RejectsBadRows` |
| 8 个写入者并发 + 1 个拉取者边拉边推进游标 | 最终看到全部 480 行，一行不漏 | `ConcurrentWriters` |
| 用户 B 拉取 | 看不到用户 A 的数据；无 token / 假 token → 401 | `UserIsolation` |
| 生产模式用默认 JWT 密钥启动 | 拒绝启动 | `TestLoadConfigProdRejectsDefaultSecret` |

训练记录模块追加的用例：`WorkoutFieldMerge`（开始取早、结束取晚）、`WorkoutMergeEchoedToUploader`（合并结果必须回传）、`SetNewFieldsSurviveOldClient`（旧客户端不清空新字段）、`WorkoutDoneFollowsSets`（done 由 sets 派生）、`BlockFields`（`blockId` / `trackVer`）、`WarmupFlag`（热身组不算最好成绩）、`ThreeTablePagination`（三表归并不重不漏）。

### P3 / M1 端到端

> 逐条标了当前覆盖情况。**没覆盖的如实写「未覆盖」**，别让人以为已经测过。

| 验收项 | 覆盖情况 |
|---|---|
| `test-sync.js` 两台模拟设备：A 记录 → B 拉到 | ⚠️ **部分**：有「换设备拉回」（清空本地 + 重新登录，顺序模拟同一用户），没有两套独立状态并发 |
| A 取消 → B 消失 | ❌ **未覆盖**（墓碑在同设备内的收敛有测，跨设备没有） |
| A 改设置 → B 训练日队列一致 | ❌ **未覆盖**（配置应用有单设备测试，跨设备一致性没有） |
| 飞行模式完整练一次 → 恢复网络后 30 秒内自动上传完 | ⚠️ **部分**：断网时队列保留、恢复后补传成功有测；「完整练一次」与 30 秒时窗没测 |
| 上传途中继续改数据 → 新改动不丢 | ✅ 已覆盖（`ackConfig` 只清「发出后没再改过」的） |
| 后端停掉 → 小程序照常记录、照常看统计、无报错弹窗 | ✅ 已覆盖（500 / 网络错误时不抛异常、队列保留） |

## 7. 风险与应对

| 风险 | 影响 | 应对 | 状态 |
|---|---|---|---|
| **备案卡住** | 正式版上不了线 | 第一天提交；开发不受影响（§技术方案 2）；备选云托管免备案 | ❌ 未处理（P0 没启动） |
| 同步漏数据 / 出重复 | 用户记录错乱，难查 | 自然主键 + rev 游标 + 并发集成测试（§5 P1）；P4 专门做改时钟测试 | ✅ 已缓解（15 个集成测试含并发与时钟偏差） |
| 老用户首次全量上传量大 | 首次同步慢 | 分批 500 行；一年约 2400 行 = 5 批，几秒完成 | ✅ 已实现 |
| 用户在新设备上抢先走完引导 | 新配置覆盖旧设备的配置 | 欢迎页在同步完成前先尝试拉取（`sync.ready()`，4 秒上限）；被覆盖的只是设置，训练记录不受影响 | ✅ **已解决**（C5-a） |
| 本地存储写满 10MB | 无法再记录 | 按月分 key 后约 20 年；届时再做本地归档 | ✅ 已缓解（C1 分片） |
| 审核被拒 | 上线延期 | 隐私协议提前写；不采集与功能无关的信息 | ❌ 未处理（P6） |
| 只有 1 人开发 | 进度不稳 | 每个阶段结束都是可停状态（§4） | — |
| **Docker Desktop 常占 8080** | 后端 `bind tcp :8080` 直接失败，联调起不来 | 本机统一用 **18081**（`ADDR=:18081` + `config.js` 的 develop）；已写进 `config.js` 注释 | ✅ 已规避 |
| **`wx.login` 的 code 每次不同** | `DEV_MODE` 把 openid 映射成 `dev-` + code，于是**每次重新登录都是新用户**：清缓存 / 换设备后数据拉不回来，M1 的「另一账号视角拉回」根本没法手动验证 | 开发版用固定 `DEV_LOGIN_CODE = 'local-1'`（`config.js` 的 `devCode()`，只在 develop 环境生效）；体验版 / 正式版仍走真实 `wx.login` | ✅ 已规避 |
