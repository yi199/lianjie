## 1. 文档体系：一份事实只写一处

| 文档 | 回答什么 | 改动频率 | 读者 |
|---|---|---|---|
| [`技术方案.md`](./技术方案.md) | 为什么这么设计（架构、同步模型、一致性取舍） | 低 | 决定方向的人 |
| [`开发计划.md`](./开发计划.md) | 分几个阶段、谁先做、验收标准 | 中 | 排期的人 |
| [`设计文档/<模块>.md`](./设计文档/README.md) | 这个模块的表、业务规则、边界情况 | 低 | 实现的人 |
| [`接口/HTTP契约.md`](./接口/HTTP契约.md) | 端点、字段、校验、错误码 | 中 | 两端实现的人 |
| [`接口/<模块>.md`](./接口/README.md) | 客户端数据层函数签名、状态 | **高** | 写页面的人 |
| [`设计文档/进步可视化.md`](./设计文档/进步可视化.md) | 业务向指标体系设计（V1–V3） | 低 | 产品侧 |

**规则**：

1. **同一个事实只写一处**，别处放链接。字段写在 HTTP 契约里，表结构写在设计文档里，函数签名写在接口文档里。
2. **改设计先改文档，再改代码。** 设计文档和契约冲突时以设计文档为准，并在同一批改动里把冲突合入契约。
3. **没实现的模块不写文档。** 等实现时一起写，否则写的是很快过期的规格。

## 2. 接口文档纪律

详见 [`接口/README.md`](./接口/README.md)，三条硬规则：

| 规则 | 说明 |
|---|---|
| **分层不重叠** | HTTP 只有一份（`接口/HTTP契约.md`）；每模块一份客户端接口；表结构在设计文档 |
| **签名冻结** | 标「待实现」的方法，名字/参数/返回值写进文档即视为契约；要改先改文档 |
| **状态诚实** | 只有「已实现 / 待实现 / 已废弃」三态，不允许「大概是这样」 |

**加、改、删任何数据层导出函数，必须同批更新对应接口文档。** PR 模板里有勾选项。

## 3. 分层与依赖纪律

```
页面（pages/*）          只调数据层，同步返回；不碰 wx.request、不碰 storage
    ▼
数据层（db.js / catalog.js / storage.js）   读写本地 + 标脏
    ▼
sync.js                  唯一的网络出口
    ▼
Go 后端 + PostgreSQL
```

| 规则 | 为什么 |
|---|---|
| **页面只调数据层** | 页面不管「数据从哪来」。这样换数据源不用改页面 |
| **数据源单一入口** | 动作来源这类东西只能有一个仓库模块（如 `utils/catalog.js`），所有消费方都依赖它 |
| **禁止循环依赖** | `db.js` 依赖 `data/plan.js`，所以 `plan.js` 绝不能反过来依赖 `db.js`——CommonJS 会拿到未赋值的空 exports，启动即崩（动作库设计 §E2） |
| **无状态模块不依赖有状态模块** | `catalog.js` 不能要 `db.js` 的 `plans()`/`decorate()`；这类函数要留在 `db.js` 里组合（动作库设计 R2） |
| **服务端校验是唯一真相** | 客户端对未知枚举的降级必须发生在**写库前**，不能把未知值送上去赌服务端宽容（动作库设计 §7.6） |

## 4. 数据与同步纪律

项目是**本地优先**：本地存储是权威，服务端负责跨设备与备份。

| 规则 | 说明 |
|---|---|
| **写本地 → 标脏 → 后台推** | 写操作不发请求，立即生效；同步失败也不能影响用户操作 |
| **自然主键去重** | `sets` 用 `(user_id, date, ex_id, set_no)`，重复上传只会覆盖，所以「失败整批重来」永远安全 |
| **删除用墓碑** | `done = false`，跨设备传播；物理删除只在「本机清空」时做 |
| **冲突看 `updated_at`（LWW）** | 客户端时刻比服务器快超过 2 分钟按服务器记（时钟夹紧） |
| **拉取只看 `rev`，不看时间** | 混用两台机器的时钟会静默漏行 |
| **派生字段不进历史行** | 凡是会随内容变化的值，都不能写进已存记录并参与后续判断（见 §5-1） |
| **已发出的 id 永不变、永不复用** | 它是历史记录的一部分；下架用 `retired` 标记，不删行 |
| **失败必须可见** | 服务端拒绝的行会出队不再重试，所以必须让用户看得到原因（见 §5-5） |

## 5. 六条硬约束

每条都指到具体代码，都是「不改就会静默丢数据或毁历史」的级别。

| # | 约束 | 依据 |
|---|---|---|
| 1 | **不要把内容版本加进 `planSig()`** | 它被写进每条组记录（`db.js:904`），轮转靠它过滤历史（`db.js:626-630`）；内容版本每次导入都 +1 → 每次改文案都重置所有用户的 A/B/C 轮转 |
| 2 | **枚举值不能只加一半** | 现有筛选全是等值比较（`db.js:1327`、`builder/index.js:178`、`exercises.js:247`）；加 `place:'both'` 会让动作在两个主模式下永久隐身 |
| 3 | **客户端生成的值要对齐服务端校验** | `validate.go:49` 卡 `ex_id ≤ 16`；超长会让用它记的**每一组**被拒，且不再重试 → 静默丢组 |
| 4 | **`/sync` 加资源要改版本号分配数** | `store.go:239` 的 `n` 决定 `users.rev` 一次涨多少；漏算会让多出来的行拿到区间外的 rev，永远拉不到 |
| 5 | **被拒的行不能静默消失** | `sync.js:220` 收到 `rejected` 直接出队；`storage.js:411-422` 的 kind 映射不认新资源时，失败就完全无声 |
| 6 | **别假设「空闲就会轮询」** | `scheduleIdlePoll()`（`sync.js:256-260`）没积压直接 return；任何依赖定时拉取的设计都要先看调度函数第一行有没有 early return |

**兜底值也不能猜**：查不到东西时的默认值会被当成真实数据用。`part: 'legs'` 这种兜底会把未知动作静默归到腿，污染统计——兜底成空值，让统计显示「未分类」。

## 6. 测试标准

| 层 | 命令 | 什么时候跑 |
|---|---|---|
| 数据层 | `cd app && node test.js` | 每次提交 |
| 页面逻辑 | `cd app && node test-page.js` | 每次提交 |
| 训练数据层 | `cd app && node test-training.js` | 每次提交 |
| 同步调度 | `cd app && node test-sync.js` | 每次提交（改了 sync/db 必须跑） |
| 后端 | `cd server && go test ./...` | 改了 server |
| 后端集成 | `TEST_DATABASE_URL=… go test ./...` | 改了 `store.go` / `schema.sql` |

**新增功能至少要有的用例**：

| 改动类型 | 必须加 |
|---|---|
| 数据层函数 | 正常路径 + 空/缺参数 + 与既有数据的交互 |
| 同步相关 | 断网后恢复、服务端 500、坏行被拒、重复上传不出重复行 |
| 新增字段 | 「旧客户端不传这个字段」时的行为（null 不覆盖） |
| 修改已有语义 | 一条「历史数据仍按老规则」的回归用例 |

当前基线：前端 **326** 个断言（114 + 47 + 122 + 43），后端 **30** 个（13 单元 + 17 集成）。

## 7. 提交前检查

```
□ 四套前端测试全绿（改了前端）
□ go build ./... 和 go test ./... 全绿（改了后端）
□ 微信开发者工具编译无报错，手动点过改动的页面
□ 加了/改了数据层函数 → 更新了 docs/接口/<模块>.md
□ 改了 HTTP 端点或字段 → 更新了 docs/接口/HTTP契约.md
□ 改了表结构 → 更新了 docs/设计文档/<模块>.md §数据模型
□ 提交信息写了「做了什么」，PR 描述写了 Closes #<issue>
```

`go build` 绿不等于测试编译得过——`go vet` 和测试文件里的错误只有 `go test` 会暴露。

## 8. 上线前检查

| 项 | 说明 |
|---|---|
| 域名备案 | API 域名和 CDN 域名**一起备案**，别分两次提交 |
| 合法域名 | `request` 白名单要配 API 域名；`<image src>` 通常不走白名单但 `downloadFile` 走——**真机各验一次** |
| 静态资产防抓 | CDN 的 Referer 白名单（放行 `servicewechat.com`）；大图放在登录接口后面 |
| 限流 | 免登录接口用独立的限流器，别复用登录的（`mainLimit` 是 1 r/s、burst 10） |
| 备份 | `pg_dump` 定时 + 真的从备份恢复一次 |
| 监控 | `/readyz` 接外部拨测；日志里 5xx 比例告警 |

## 9. 代码风格

不单独定规范，跟着仓库现有风格走：

- 小程序端不用构建工具、不加 npm 依赖，`require` 相对路径
- 数据层函数**同步返回**，只有网络相关才返回 Promise
- 注释写「为什么」，不写「做什么」
- 后端用标准库 `net/http` 的 method 路由，不引框架
