# 身体指标（P5）

> 上位文档：[技术方案](../技术方案.md)（本地优先、同步协议）· [HTTP 契约](../接口/HTTP契约.md)（`metrics` 端点与字段）
> 状态：**v0.1 已实现**（存储 / 录入页 / 趋势图）。评级与「用体重换算自重负荷」属于进步可视化 V3，还没做。

## 1. 解决什么问题

前面所有页面都在说「练了多少」（组数、吨数、地形），但没有一处回答「身体变了吗」。身体指标补的是这一维度：体重、体脂率、腰围、静息心率。

设计上守两条：

1. **一天一个值**。不记「第几次」，同一天再填就是改，主键 `(kind, date)` 天然幂等。
2. **只采集用户主动填的**。不接体脂秤 SDK、不做身材对比图（红线：不做身材对比）。

## 2. 核心概念

| 概念 | 定义 | 例子 |
|---|---|---|
| 指标种类 `kind` | 服务端固定的 9 种枚举，前端只用其中 4 种 | `weight` / `bodyfat` / `waist` / `hrrest` |
| 记录 | 某天某个指标的一个值 | 2026-11-04 体重 74.8kg |
| 序列 | 同一 kind 的全部有效记录，按日期升序 | 用于画趋势 |
| 墓碑 | `done=false` 的记录，等于「这天这条被删了」 | 同步系统里删除必须这样表达 |

## 3. 数据模型

服务端 `metrics` 表早就有（见契约 §1.2 / §2）：

```
(user_id, kind, date) 主键 · value · unit · note · done · updated_at · rev
```

客户端本地按月分片，和组记录同一套机制：

```
lj.metrics.months      ['2026-10','2026-11']
lj.metrics.2026-11     [ {kind, date, value, unit, note, done, updatedAt}, … ]
lj.sync.dirty          { 'm:weight|2026-11-04': updatedAt, … }
```

一个月最多 9 种 × 31 天 ≈ 28KB，一年约 330KB —— 按月分就够了，不必再按年。

## 4. 用户流程

```
我的 → 身体指标
  ├── 顶部大数字：最近一次的值 + 比 30 天前的变化
  ├── 四个切换：体重 / 体脂率 / 腰围 / 静息心率
  ├── 趋势图：最近 30 次记录（直线段 + 面积渐变 + 末点陶土色）
  ├── 最近记录：最近 8 条，今天那条右边有 ×（删）
  └── 底部录入条：今天日期 + 数字 + 「记下」
```

录入只需要两步：点开 → 输数字 → 记下。不弹键盘以外的任何选择器。

## 5. 业务规则

| 规则 | 为什么 |
|---|---|
| 每种 kind 有 `min/max/step`，超范围**直接拒绝**而不是裁剪 | 手滑输 500kg 应该当场发现，不该被「修正」成 300 |
| 按 step 取整（体重 0.1 / 腰围 0.5 / 心率 1） | 显示层不留浮点尾巴（`75.10000000000001`） |
| 空输入不写库 | 和「填 0」区分开，0 是合法值（比如体脂秤测不出除外） |
| 删除：同步开 → 墓碑；同步关 → 物理删 | 没有别的设备需要通知时不留垃圾 |
| 变化量默认比 30 天前（找不到就返回 null，不编造） | 少数据时宁可显示「—」 |

## 6. 同步

- 上传：`dirtyBatch` 把 `m:` 前缀的 id 一起带出，`/sync` 的 `metrics` 字段
- 下发：`applyRemoteMetrics` —— 本地有未上传改动就先不动（等它上传后由服务端裁决），墓碑直接物理删
- 幂等：`(kind,date)` 是自然主键，重复上传只会覆盖
- 首次全量：`markAllDirty()` 会把本地全部指标排进队列

## 7. 接口

客户端数据层（`utils/db.js`）：

```js
metricKinds()                     // [{kind, cn, en, unit, step, min, max}]
metricDef(kind)                   // 单个定义
metricOf(kind, date?)             // 某天的值（不含墓碑）
saveMetric({kind, date?, value, note?})   // 存/覆盖；参数不合法返回 null
removeMetric(kind, date?)         // 墓碑或物理删
metricSeries(kind, {from,to,limit})       // 序列，升序
latestMetric(kind)                // 最近一次
metricDelta(kind, days=30)        // {now, before, delta, days, beforeDate}
```

页面：`pages/metrics/index`（已注册进 `app.json`，从「我的」进入）。

## 8. 数据量

一天 4 条、一条约 90 字节 → 一年 130KB，五年 660KB。同步一次只传改动的那几行。

## 9. 已知边界

- **同一天只能一个值**：早晚各称一次只留最后一次。真要记多次得改成 `(kind,date,seq)`，会牵动服务端主键，暂不做。
- **体重没有和训练关联**：自重动作的实际负荷换算（`体重 × 系数`）属于进步可视化 V3。
- **没有提醒**：「体重多久没更新就提醒」列在进步可视化 §13 待定。
- **趋势图按记录条数均分横轴**，不按日期间隔 —— 数据本来就不均匀，等距更好读；代价是「停了两周」在图上不明显。
