## 3. 验收标准

### A. 静态检查

```bash
cd server
go build ./...      # 无输出
go vet ./...        # 无输出
gofmt -l .          # 无输出
```

### B. 单元测试（不需要数据库）

```bash
cd server && go test ./...
```

**要求：13 个测试函数全部 PASS**，其中本分支新增 2 个：

| 测试 | 覆盖 |
|---|---|
| `TestValidateWorkout` | `startedAt` 必填/格式、`finishedAt` 可空且不早于开始、`feel` 1–5、`note` ≤200 字 |
| `TestValidateSetNewFields` | 新字段全空时旧客户端照常通过；全填时通过；`slot`/`rir`/`targetSets` 越界与 `completedAt` 格式错被拒 |
| `TestPagePull`（扩展） | 新增子用例「三张表混合 → 按 rev 升序归并，不重不漏」 |

### C. 集成测试（需要真 Postgres）

```bash
cd server
docker compose up -d db
TEST_DATABASE_URL='postgres://lianjie:lianjie_dev_pw@localhost:5432/lianjie?sslmode=disable' \
  go test ./... -count=1
```

**要求：14 个集成用例全部 PASS**，其中本分支新增 4 个：

| 用例 | 场景 | 期望 |
|---|---|---|
| `TestIntegrationWorkoutFieldMerge` | 两台设备同一天都上传 workout，开始时刻不同 | `started_at` 取**较早**的 09:30；`finished_at` 取**较晚**的 11:30；`planKey` 按 LWW 取 `updatedAt` 更新的一方 |
| `TestIntegrationSetNewFieldsSurviveOldClient` | 新客户端先传带新字段的组，旧客户端再传同一组（不带新字段、但 `updatedAt` 更新） | `weight` 按 LWW 变成新值；**7 个新字段一个都没被清空** |
| `TestIntegrationWorkoutDoneFollowsSets` | 组与训练同批到达 → 组全部墓碑 → 再完成一组 → 另建一个没有组的日期 | `done` 依次为 `true → false → true`；没有组的那天为 `false` |
| `TestIntegrationThreeTablePagination` | 600 组 + 300 训练 + 150 指标，从游标 0 全量拉 | 三张表**不重不漏**，且确实走了多页（`pages ≥ 2`） |

**同时要求既有 10 个集成用例无回归**（幂等重试、回声剔除、LWW、时钟偏差、墓碑、分页、坏行隔离、配置 LWW、用户隔离、并发写）。

### D. 向后兼容

| 项 | 要求 |
|---|---|
| 老库升级 | 已有 `sets` 数据的库启动后，7 个新列被加上且**原有数据不变**（`alter ... add column if not exists` 只加列） |
| 旧客户端 | 不带 `workouts`、不带新字段的请求照常 200，行为与改动前一致 |
| 新客户端 | 传 `workouts` 与新字段时正常写入 |

### E. 文档一致性

`/sync` 的请求/响应字段必须与 `docs/后端接口契约.md` 一致。
**注意：契约此刻仍是 v2（没有 workouts），本分支需要一并把契约升到 v3**——这是合并前必须补的最后一步。

## 4. 什么情况算验收不通过

以下任意一条成立即驳回（不是「注意一下」，是 fail）：

1. **三张表分页漏行或重行**——同步系统最严重的缺陷，且难发现
2. **workouts 被写成整行 LWW**——较早的 `started_at` 被覆盖，训练时长算错
3. **旧客户端上传后新字段变 `null`**——新数据被无声清空
4. **`workouts.done` 与 `sets` 不一致**——尤其「先到组、后到训练」和「先到训练、后到组」两种顺序结果不同
5. **既有 10 个集成用例任何一个回归**
6. 老库升级后 `sets` 原有数据变化
