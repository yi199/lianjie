# 模块设计 · 有氧记录

> 范围：有氧类训练（跑步、单车、跳绳、划船机等）的**动作体系、记录结构、热量估算与统计**。
> 有氧和力量训练的数据形状完全不同（没有重量和组数，而是时长、距离、热量），所以单独成一套动作体系和一张记录表，不混进组记录。
> 关联：怎么排进日程见 [`训练日程.md`](./训练日程.md)；力量训练的记录见 [`训练记录.md`](./训练记录.md)。

## 1. 为什么单独一套

| 如果混进组记录 | 后果 |
|---|---|
| 用 `weight` `reps` 硬塞时长和距离 | 字段含义随动作变化，没人看得懂 |
| 吨数、PR、加重建议、部位分布 | 每一处都要记得排除有氧，漏一处数字就错 |
| 有氧需要的热量、心率、距离 | 组记录没有地方放 |

单独一套之后：力量看组数、吨数、PR；有氧看时长、距离、热量，**互不污染**。

现有动作库里有几个计时类的「有氧化」动作（开合跳、波比跳、高抬腿、登山跑），它们作为**力量训练里的计时动作**保留不动；真正的有氧项目放进新的有氧动作库。

## 2. 有氧动作库

新文件 `app/data/cardio.js`，和力量动作库 `exercises.js` 并列。每个动作**声明自己需要记录哪些字段**，记录页按声明渲染输入项：

```js
{
  id: 'c1', cn: '跑步', en: 'Running',
  place: 'both',                         // gym | home | both（户外跑算 both）
  fields: ['duration', 'distance', 'calories', 'avgHr'],   // 显示哪些输入项，按顺序
  primary: 'distance',                   // 进步看哪个：距离 / 时长 / 次数
  met: 9.8,                              // 估算热量用（§4），约 10 km/h 配速的典型值
  extras: []                             // 动作专属字段，见下
}
```

### 2.1 首批动作

| id | 动作 | 记录字段 | 专属字段 | 进步看 |
|---|---|---|---|---|
| c1 | 跑步（户外 / 跑步机） | 时长、距离、热量、平均心率 | 坡度（跑步机） | 距离 |
| c2 | 快走 | 时长、距离、热量 | 坡度 | 时长 |
| c3 | 单车 / 动感单车 | 时长、距离、热量、平均心率 | 阻力档位 | 时长 |
| c4 | 椭圆机 | 时长、热量、平均心率 | 阻力档位 | 时长 |
| c5 | 划船机 | 时长、距离、热量 | 阻力档位、桨频 | 距离 |
| c6 | 爬楼机 | 时长、热量 | 档位、层数 | 时长 |
| c7 | 跳绳 | 时长、次数、热量 | — | 次数 |
| c8 | 游泳 | 时长、距离、热量 | 泳姿 | 距离 |
| c9 | HIIT / 有氧操 | 时长、热量、平均心率 | — | 时长 |

MET 值取自运动能量消耗手册（Ainsworth 等，Compendium of Physical Activities），实现时逐项核对，并随专业体系校准。

### 2.2 字段字典（统一定义，各动作按需选用）

| 字段 | 单位 | 范围 | 说明 |
|---|---|---|---|
| `duration` | 秒 | 1–86400 | **必填**。界面按分钟输入 |
| `distance` | 米 | 0–500000 | 界面按公里输入（游泳按米） |
| `calories` | 千卡 | 0–10000 | 手动填写（器械 / 手表读数）或估算 |
| `avgHr` | 次/分 | 30–250 | 平均心率 |
| `count` | 次 | 0–100000 | 跳绳次数等 |
| `extras` | — | ≤ 1KB JSON | 坡度、档位、泳姿等动作专属字段 |

## 3. 有氧记录

### 3.1 表结构

```sql
create table if not exists cardio (
  user_id      bigint        not null references users(id) on delete cascade,
  date         date          not null,
  ex_id        text          not null,              -- 'c1'
  seg_no       smallint      not null,              -- 同一天同一动作的第几段（间歇跑分段时用），从 1 起
  primary key (user_id, date, ex_id, seg_no),

  ex_cn        text          not null default '',   -- 冗余存名称
  block_id     text          not null default '',   -- 属于今天的哪个训练块（训练日程 §6）
  track_ver    integer,

  duration_sec integer       not null,
  distance_m   numeric(9,1),
  calories     numeric(7,1),
  calories_est boolean       not null default false, -- true = 估算值，不是读数
  avg_hr       smallint,
  count        integer,
  extras       jsonb         not null default '{}'::jsonb,

  target       jsonb,                               -- 当时的目标：{ "durationMin": 20 } / { "distanceKm": 5 }
  completed_at timestamptz,
  done         boolean       not null default true, -- false = 墓碑
  updated_at   timestamptz   not null,
  rev          bigint        not null
);

create index if not exists cardio_user_rev_idx     on cardio (user_id, rev);
create index if not exists cardio_user_ex_date_idx on cardio (user_id, ex_id, date desc);
```

同步方式与组记录完全一致：自然主键幂等、整行 LWW、墓碑、版本号游标；`/sync` 增加 `cardio` 数组。可空字段同样用 `coalesce` 合并，旧客户端不会清空新字段。

### 3.2 本地存储

`lj.cardio.YYYY`：按年分 key（有氧一年几百条，约 60KB），与组记录、一次训练共用待上传队列，队列 id 前缀 `c:`。

### 3.3 一次有氧怎么记

```
选有氧动作（来自计划线或临时添加）
  → 预填：计划目标（20 分钟），或上次的时长 / 距离
  → 结束后填实际：时长（必填）、距离 / 热量 / 心率（按动作，可不填）
  → 保存 = 一段（seg_no = 1）
  → 间歇训练可以「再加一段」（seg_no = 2 …）
```

和力量不同，有氧不需要组间休息计时；以后可以加「开始计时 → 结束」的秒表模式，结束时自动填时长。

## 4. 热量

| 来源 | 做法 | 标注 |
|---|---|---|
| 手动填写 | 器械屏幕、手表上的读数 | 不标注 |
| 估算 | `热量（千卡）= MET × 体重（kg）× 时长（小时）` | 界面标「估算」，`calories_est = true` |
| 没有体重 | 不估算，热量留空 | 提示「填写体重后可估算热量」 |

- 体重取**那天之前最近一次**记录的体重（和进步可视化的口径一致，见 `../进步可视化.md` §8.3）
- 估算只到量级，不同人、不同强度误差可达 20% 以上；统计里估算值和读数照常相加，但汇总处注明「含估算」
- 力量训练的热量**不估算**：MET 方法对力量训练很不准，给出来反而误导

## 5. 统计与展示

| 指标 | 计算 | 出现在 |
|---|---|---|
| 时长 | Σ duration | 战报、数据页 |
| 距离 | Σ distance（按动作分别汇总，跑步和游泳的距离不相加） | 战报、数据页 |
| 热量 | Σ calories（含估算时注明） | 战报、数据页 |
| 有氧天数 | 有有氧记录的天数 | 数据页 |
| 进步 | 按动作的 `primary`：同距离用时变短（配速）、同时长距离变长、次数变多 | 进步可视化（另行设计） |

**不参与**：吨数、PR（重量）、部位分布、加重建议。

战报里有氧是单独一段：「跑步 5.2 km · 28 分钟 · 约 320 千卡（估算）」。

训练天数、本周进度：有氧和力量**都算**「这天练了」。

## 6. 接口

### 6.1 客户端数据层（新增）

| 方法 | 作用 |
|---|---|
| `cardioExercises({ place? })` | 有氧动作库 |
| `cardioPrefill(exId, date?)` | 预填：计划目标 / 上次成绩，下一段的 `segNo` |
| `saveCardio({ date, exId, segNo, durationSec, distanceM?, calories?, avgHr?, count?, extras?, blockId?, target? })` | 保存或修改一段；没填热量且有体重时自动估算 |
| `uncheckCardio({ date, exId, segNo })` | 删除一段（墓碑或物理删除，规则同组记录） |
| `cardioDay(date?)` | 某天的有氧记录与汇总 |

`todayWorkout` / `todayReport` 增加有氧部分（见 `训练记录.md` v0.3）。

### 6.2 服务端

| 改动 | 说明 |
|---|---|
| 新表 `cardio` | §3.1 |
| `/sync` | 请求和响应增加 `cardio` 数组；单批 500 行上限把它计入；拉取分页从三张表扩到四张表（按 rev 归并） |
| `workouts.done` | 由「这一天是否还有 done=true 的组记录**或有氧记录**」重新计算 |
| `/history/summary` | 增加有氧汇总（可选） |

## 8. 验收标准

| 场景 | 期望 |
|---|---|
| 跑步 20 分钟 5 km，不填热量，有体重 | 自动估算热量并标注「估算」 |
| 没有体重记录 | 热量留空，有提示 |
| 同一天跑步两段（间歇） | seg_no 1、2，汇总时长相加 |
| 只做了有氧的一天 | 算训练天数；吨数为 0；战报只有有氧段 |
| 有氧不影响力量 | PR、加重建议、部位分布、吨数和没有有氧时完全一致 |
| 删除一段有氧（开同步） | 墓碑同步到其他设备；当天没有任何记录时训练消失 |
