## 1. 模块概述

### 1.1 要解决什么

健身者往往同时在跑好几套计划：

- 胸 → 背 → 肩 三分化循环，练三休一
- 二头三头单独一套，两天一练
- 腹部两天一练
- 有氧每周一三五

现在的产品只有「一个方案、一个训练日队列」，表达不了这种组合。本模块让用户：

1. 提前定制多套计划，每套像苹果闹钟一样设定**几天一次**
2. 首页看到**今天到期的所有计划**，按顺序一项项做，可以临时调整
3. 数据页日历里，每一天用**几种颜色**看到练了什么、将要练什么（往后 3 个月）
4. 当天临时改了动作，可以**一键同步到这套计划以后的每一次**

### 1.2 设计原则

| 原则 | 含义 |
|---|---|
| **未来不存，只存规则** | 日历上未来 3 个月的安排全部由「计划线 + 重复规则 + 已完成记录」现算。规则一改，日历自动重算，不会有过期的日程数据 |
| **内容轮转按完成，不按日期** | 胸背肩循环不管哪天练，都是做完胸才轮到背。跳过一天不会漏掉背（沿用现有「训练日排队」的思路） |
| **只存用户改过的那一天** | 今天的安排默认由规则推算；只有用户手动调整过的日子才存一份 |
| **老用户零操作** | 现有的「当前方案」自动迁移成第一条计划线，行为和现在一致 |

### 1.3 功能清单

| # | 功能 | 页面 |
|---|---|---|
| T1 | 创建 / 编辑 / 停用 / 删除计划线 | 我的 → 训练计划（新） |
| T2 | 设定重复规则（4 种）与错过后的处理方式 | 同上 |
| T3 | 计划线颜色、优先级（首页排序） | 同上 |
| T4 | 今日安排：列出今天到期的所有计划线 | 训练（today） |
| T5 | 今日临时调整：调顺序、跳过、加一项、改动作 | 训练（today） |
| T6 | 改了动作后选择「仅今天 / 同步到以后」 | 训练（today / record） |
| T7 | 日历：过去显示实际完成，今天显示进度，未来 3 个月显示预计 | 数据（stats） |
| T8 | 本周进度：总训练天数 + 每条计划线的完成情况 | 训练、数据 |
| T9 | 完成计划后是否看战报（每次问 / 自动 / 不提示） | 训练、我的 |

## 2. 核心概念

| 概念 | 定义 | 例子 |
|---|---|---|
| **计划线（track）** | 一套独立循环的训练计划：有自己的内容、重复规则、颜色。界面上可以叫「训练计划」 | 「胸背肩循环」「手臂」「有氧」 |
| **训练日（session）** | 计划线内容里的一项，按顺序轮转 | 胸背肩循环里的「背」 |
| **重复规则（repeat）** | 计划线多久到期一次 | 每 2 天、每周一三五、练三休一 |
| **锚定方式（anchor）** | 错过之后怎么算下一次：按日历固定，或按完成顺延 | 力量默认顺延，有氧默认固定 |
| **到期（due）** | 按规则，这条计划线今天该练了 | |
| **今日安排（agenda）** | 今天要做的训练块列表，按顺序 | ① 背 ② 手臂 ③ 跑步 20 分钟 |
| **训练块（block）** | 今日安排里的一项：来自某条计划线的一个训练日，或临时加的自由训练 / 有氧 | |
| **预计（projected）** | 日历上未来日期的安排，是按规则推算的，会随实际完成情况变化 | |

### 计划线与现有概念的关系

```
以前：  一个方案 ──展开──▶ 训练日队列 A → B → C（一条）

现在：  计划线 1：胸背肩循环   内容 = 胸 → 背 → 肩      规则 = 练三休一、按完成顺延
        计划线 2：手臂         内容 = 二头三头          规则 = 每 2 天、按完成顺延
        计划线 3：有氧         内容 = 跑步 20 分钟      规则 = 每周一三五、按日历固定
                  │
                  ▼ 每天：哪些计划线到期？各自轮到哪个训练日？
        今日安排：① 背  ② 二头三头  ③ 跑步
```

计划线的**内容**可以来自：官方方案、自定义方案、或直接在计划线里编辑的训练日（例如只有一个训练日的「手臂」）。

## 3. 用户流程

### 3.1 定制计划

```
我的 → 训练计划 → ＋ 新建
  ① 内容：从官方方案选 / 从我的方案选 / 新建训练日（选动作）/ 有氧项目
  ② 重复：每 N 天 / 每周固定几天 / 每周 N 次 / 练 X 休 Y
  ③ 错过之后：顺延（默认力量）/ 按日历（默认有氧）
  ④ 从哪天开始、颜色、名称
  → 保存 → 日历立刻显示未来 3 个月的预计
```

### 3.2 每天训练

```
训练 tab（today）
┌────────────────────────────────────────┐
│ 今天 · 周六        本周 3 天 · 胸背肩 2/3 │
│                                        │
│ ● 胸背肩循环 · 背          进行中        │  ← 优先级高的在上，先做
│   划船 3/4 · 引体 ✓ · 下拉 未练           │
│   [继续训练]                             │
│ ● 手臂 · 二头三头          未开始        │
│ ● 有氧 · 跑步 20 分钟      未开始        │
│ ＋ 今天再加一项                          │
└────────────────────────────────────────┘
（信息结构示意，不是界面设计）
```

**首页呈现（已确认方向）**：沿用现在首页「训练日卡片」的样式，每条到期的计划线一张卡片，从上往下排；卡片上加一条**进度条**表示这个训练块完成了多少（力量按已完成组数 / 计划组数，有氧按已完成时长 / 目标时长）。具体视觉由前端专题定，数据由 `todayAgenda()` 的 `status` 与进度字段提供。

- 「继续训练」进入第一个没完成的训练块；任何一块都可以直接点进去先做
- 没有任何计划线时，显示「＋ 添加」：自由训练 / 有氧 / 去定制计划
- 一个训练块做完，按偏好提示是否看今天的战报（§9）

### 3.3 查看日历

数据页月历，每一格最多显示 3 个颜色点（超出显示「+1」），点某一天看当天详情：

| 日期 | 点的样式 | 含义 |
|---|---|---|
| 过去 | 实心 | 这条计划线那天**实际做了** |
| 过去 | 空心（可选显示） | 那天到期但没做（错过） |
| 今天 | 实心 / 空心 | 已完成 / 待完成 |
| 未来 | 浅色 | **预计**：按规则推算，会随实际完成情况变化 |

可以往后翻 3 个月；更远的不显示（推算越远越不准，意义不大）。

## 4. 计划线的数据结构

计划线放在**配置文档**（`user_config.body.tracks`）里，跟设置、自定义方案一起整份同步。服务端不需要新表。

```jsonc
{
  "id": "t-1761700000000",
  "name": "胸背肩循环",
  "kind": "strength",                 // strength = 力量（组记录）；cardio = 有氧（有氧记录）
  "color": "moss",                    // 调色板里的名字，不存色值，换主题时不用迁移
  "priority": 0,                      // 首页排序，小的在上
  "enabled": true,                    // 停用 = 保留历史，不再到期
  "startDate": "2026-11-01",          // 规则从哪天开始算

  "content": {                        // 内容：三选一
    "programId": "gym-ppl-3"          // ① 引用官方 / 自定义方案（展开成训练日队列）
    // "sessions": [ { "key": "A", "name": "二头三头", "exIds": ["g8","g20","g3"] } ]   ② 计划线自带的训练日
    // "cardio": [ { "exId": "c1", "target": { "durationMin": 20 } } ]                  ③ 有氧项目
  },
  "edits": {                          // 「同步到以后」的修改，覆盖在内容之上（§7.3）
    "A": { "exIds": ["g1", "g23", "g4", "g3"] }
  },

  "repeat": { "type": "cycle", "on": 3, "off": 1 },   // 见 §5
  "anchor": "completion",             // completion = 按完成顺延；calendar = 按日历固定

  "version": 3,                       // 内容或规则每改一次 +1（§6.3）
  "createdAt": "2026-10-31T10:00:00.000Z"
}
```

| 约束 | 值 |
|---|---|
| 计划线数量 | 最多 8 条（日历一格放不下更多颜色） |
| 一条计划线的训练日 | 最多 8 个 |
| 调色板 | 8 种，和计划线上限一致；新建时自动分配一个没用过的 |
| 配置文档大小 | 64KB 上限（契约 §1.3）。8 条计划线约 6KB，足够 |

## 5. 重复规则

### 5.1 四种规则

| 类型 | 写法 | 含义 |
|---|---|---|
| 每 N 天 | `{ "type": "interval", "every": 2 }` | 两天一练 |
| 每周固定几天 | `{ "type": "weekdays", "days": [1, 3, 5] }` | 周一三五（1 = 周一 … 7 = 周日） |
| 每周 N 次 | `{ "type": "perWeek", "times": 3 }` | 一周 3 练，不固定哪天（现在的方式） |
| 练 X 休 Y | `{ "type": "cycle", "on": 3, "off": 1 }` | 练三休一、练四休一 |

### 5.2 两种锚定方式

| 锚定 | 下一次怎么算 | 默认用于 |
|---|---|---|
| **按完成顺延**（completion） | 从**上一次实际练这条计划线的那天**往后算。错过了就一直挂在今天，直到练了为止 | 力量（对应肌肉恢复：休息间隔从上次练完开始算） |
| **按日历固定**（calendar） | 从 `startDate` 起按规则排出固定日期，不管练没练。错过的就算错过 | 有氧、固定时间的课 |

### 5.3 到期判断（今天这条计划线要不要出现）

设 `last` = 这条计划线最近一次实际训练的日期，`today` = 训练日期（含跨零点规则）。

| 规则 | 按完成顺延 | 按日历固定 |
|---|---|---|
| 每 N 天 | 没练过 → 到期；否则 `today − last ≥ N` → 到期 | `(today − startDate) mod N = 0` |
| 每周固定几天 | 今天是规定的星期几 → 到期；若上一个规定日没练，今天补上也算到期（顺延到下一个非规定日为止） | 今天是规定的星期几 |
| 每周 N 次 | 本周已练次数 < N，且（今天还没练这条线）→ 到期 | 同左（「每周 N 次」本身不绑日期，两种锚定行为一致） |
| 练 X 休 Y | 统计以 `last` 结尾的连续训练段长度 `k`（相邻两次间隔 ≤ 1 天视为连续）：`k < X` 且 `today − last ≥ 1` → 到期；`k ≥ X` 时须休满 Y 天：`today − last > Y` → 到期 | 从 `startDate` 起按 `X+Y` 天为周期：周期内前 X 天到期 |

补充：

- `today < startDate` 或 `enabled = false` → 不到期
- **今天已经练过这条线** → 照常显示（状态为进行中 / 已完成），不重复判断
- 「错过」只对按日历固定的计划线有意义；按完成顺延的计划线没有错过，只有「顺延中」（距离应练日期已过 N 天，首页可提示「已顺延 2 天」）

### 5.4 内容轮转：今天练这条线的哪个训练日

和现有 `nextKey` 规则一致，只是范围限定在这条计划线：

```
今天已经练过这条线 → 继续今天那个训练日
否则 → 这条线最近一次训练的训练日的下一个（到末尾回到第一个）
从没练过 → 第一个
```

只认**当前版本**的计划线记录（§6.3）。

### 5.5 预计（日历的未来部分）

从今天往后逐日模拟，**假设每个到期日都按时完成**：

```
状态 = 当前的 last、本周次数、连续段长度、轮转位置
for day in 明天 … 今天 + 3 个月:
    if 到期(day, 状态):
        记一个预计点（计划线颜色 + 该轮到的训练日名称）
        状态 = 把 day 当作「已练」更新（last = day，轮转到下一个训练日 …）
```

- 3 个月 × 8 条计划线 ≈ 720 次判断，手机上一毫秒内完成，不需要缓存
- 按完成顺延的计划线：今天没练，所有未来的点会整体后移——这是正确的，界面要用浅色表明「这是预计」
- 「每周 N 次」没有固定日期，预计时把本周剩余次数**平均分布**在本周剩余的日子里（例：周三还剩 2 次 → 周四、周六），只用于日历展示

## 6. 记录如何归属到计划线

### 6.1 组记录、有氧记录、一次训练的新字段

| 字段 | 加在 | 说明 |
|---|---|---|
| `block_id` | `sets`、`cardio`（新表，见有氧记录） | 这条记录属于今天的哪个训练块。计划线的训练块 = 计划线 id；临时加的自由训练 = `adhoc:<id>` |
| `track_ver` | `sets`、`cardio` | 记录时计划线的版本号（§6.3） |
| `plan_key` | 已有 | 计划线里的训练日编号 |

`workouts`（一次训练）保持一天一行，是当天所有训练块的容器，不加字段。

### 6.2 为什么需要 `block_id`

同一天，两条计划线可能包含同一个动作（胸背肩里有窄距卧推、手臂里也有）。组记录主键是 `(日期, 动作, 组号)`，组号会接着往下编，不会撞；但不加 `block_id`，就分不清哪几组算哪条计划线，轮转、日历、本周进度都会错。

### 6.3 计划线版本号（替代原来的计划签名 `sig`）

现在用 `sig = 水平|频率|场所|方案id` 判断「改设置之后旧记录不参与轮转」。有了计划线以后，改为按计划线判断：

| 发生了什么 | `version` | 影响 |
|---|---|---|
| 改重复规则、颜色、名称、优先级 | 不变 | 只影响以后的到期日和日历，轮转接着走 |
| 改内容的训练日**结构**（增删训练日、换方案） | +1 | 旧版本的记录不再参与这条线的轮转，从第一个训练日重新开始；历史记录不删 |
| 「同步到以后」改了某个训练日的动作（§7.3） | 不变 | 训练日还是那个训练日，轮转不受影响 |

旧的 `sig` 字段保留，继续写入，兼容老数据和老客户端。

### 6.4 老数据怎么办

- 迁移时，现有的「当前方案」生成计划线 `main`：内容 = 当前方案，重复 = 每周 N 次（N = 现在的「一周几练」），锚定 = 按完成顺延
- 老的组记录没有 `block_id`：读取时一律视为 `main`
- 所以老用户升级后，首页、轮转、本周进度和现在完全一样

## 7. 今日安排

### 7.1 默认安排（不存储）

```
今日安排 = 今天到期的所有计划线（按 priority 排）
         + 今天已经练过、但今天不到期的计划线（比如提前练了）
         + 今天临时加的训练块（只在改过时存在，见 7.2）
每个计划线训练块 = 该计划线今天轮到的训练日（§5.4）
```

撞在同一天的计划线**全部显示**，由用户决定做哪个、先做哪个。没做的那条：按完成顺延的明天继续到期；按日历固定的记为错过。

### 7.2 今日临时调整（只存改过的日子）

| 操作 | 效果 |
|---|---|
| 调整顺序 | 只影响今天的显示顺序 |
| 跳过一项 | 今天不显示。按完成顺延的计划线：明天继续到期；按日历固定的：记为错过 |
| 加一项 | 临时加：自由训练 / 有氧 / 某条计划线的下一个训练日（提前练） |
| 改动作 | 在这个训练块里增、删、换动作，见 7.3 |

存储：新表 `agendas`，一人一天一行，整份 LWW。

```sql
create table if not exists agendas (
  user_id     bigint      not null references users(id) on delete cascade,
  date        date        not null,
  blocks      jsonb       not null,   -- 见下
  updated_at  timestamptz not null,
  rev         bigint      not null,
  primary key (user_id, date)
);
```

```jsonc
// blocks：只描述「和默认安排不同」的地方，没有提到的计划线照默认处理
[
  { "id": "t-1", "order": 0 },                                   // 调了顺序
  { "id": "t-2", "skipped": true },                              // 跳过
  { "id": "adhoc:1761", "type": "free", "title": "加练手臂", "order": 2 },
  { "id": "t-3", "exIds": ["g1", "g23", "g4"] }                  // 今天改了动作（仅今天）
]
```

只存差异，是为了让「规则改了之后，没改过的部分自动跟着变」。

不放进 `workouts`：那张表的 `done` 由组记录推算，只有安排、还没开练的一天会被当成取消。

### 7.3 改了动作：仅今天 / 同步到以后

用户在某个训练块里增删换了动作（例如胸日把哑铃飞鸟换成绳索夹胸），保存时选择：

| 选择 | 写到哪 | 效果 |
|---|---|---|
| **仅今天** | `agendas` 当天的 `exIds` | 今天按新动作练，以后照旧 |
| **同步到以后** | 计划线的 `edits[训练日]`（配置文档） | 以后每次轮到这个训练日都用新动作；今天也生效 |

- 计划线内容引用的是官方方案时，改动只写进这条计划线的 `edits`，**不改官方方案本身**；引用的是自定义方案时，同样写进 `edits`，不改动方案（同一个方案可能被多条计划线共用）
- 「同步到以后」不改变已经发生的记录，日历上过去的格子不变
- 计划线详情里可以「恢复成方案原样」= 清空这个训练日的 `edits`
- 现有的「换动作（永久替换计划里的位置）」即是「同步到以后」的一个特例，迁移为 `edits`

## 8. 本周进度

| 显示 | 规则 |
|---|---|
| 总数 | 本周有训练记录的**天数**（一天练几条计划线也只算一天） |
| 每条计划线 | 本周实际完成次数 / 本周应完成次数 |

「本周应完成次数」：

| 规则 | 应完成次数 |
|---|---|
| 每周 N 次 | N |
| 每周固定几天 | 规定的天数 |
| 每 N 天、练 X 休 Y | 按 §5.5 预计本周（周一到周日）落在哪几天，已过去的按实际 + 剩余的按预计 |

## 9. 战报提示

战报本身一天一份、现算、不存储，任何时候都能从首页或日历进入（见 [`训练记录.md`](./训练记录.md) §5.8，按训练块分段）。

「是否生成」落实为**完成后是否提示**，偏好存在配置文档：

| 偏好 `reportPrompt` | 行为 |
|---|---|
| `ask`（默认） | 今天的一个训练块完成时，弹出「看今天的战报？」可跳过 |
| `auto` | 今天**所有**训练块完成时，自动进入战报 |
| `never` | 不提示，用户自己从首页进入 |

## 10. 接口

### 10.1 客户端数据层（新增）

| 方法 | 返回 / 作用 |
|---|---|
| `tracks()` | 全部计划线（含停用的） |
| `saveTrack(track)` | 新建 / 修改，自动处理 `version` |
| `removeTrack(id)` / `setTrackEnabled(id, on)` | 删除 / 停用。删除不删历史记录 |
| `todayAgenda(date?)` | 今日安排：`[{ blockId, trackId, name, color, kind, sessionKey, sessionName, status, overdueDays, progress: { done, total, unit }, exercises }]`。`progress` 供首页卡片进度条：力量 = 已完成正式组 / 计划组数（`unit: 'set'`），有氧 = 已完成分钟 / 目标分钟（`unit: 'min'`） |
| `editAgenda(date, op)` | 调整今日安排：`{ type: 'reorder' | 'skip' | 'unskip' | 'add' | 'remove', … }` |
| `editBlockExercises(date, blockId, exIds, scope)` | 改动作，`scope = 'today' | 'future'` |
| `scheduleRange(from, to)` | 日历：`{ 'YYYY-MM-DD': [{ trackId, color, sessionName, state: 'done' | 'missed' | 'todo' | 'projected' }] }`，最多到今天 + 3 个月 |
| `weekProgress(date?)` | `{ days, tracks: [{ trackId, done, expected }] }` |

`todayWorkout` / `saveSet` 等训练记录接口增加 `blockId` 参数（见 `训练记录.md`）。
