# 加入开发指南

> 给被拉进来的队友看。管理员那一节是给你（满谦益）自己看的。

## 你需要先有

| | |
|---|---|
| Git | https://git-scm.com/downloads |
| Node.js | 用来跑自测脚本，v18+ 即可 |
| 微信开发者工具 | https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html |
| 账号 | Gitee 或 GitHub（看你从哪边拉） |

# 一、Gitee 版（国内推荐，速度快）

## 1.1 管理员操作（满谦益）

**① 拿到队友的 Gitee 用户名**（不是昵称，是 URL 里那段，比如 `man-qianyi`）。

对方没账号就先注册：https://gitee.com/signup

**② 打开仓库管理**

https://gitee.com/man-qianyi/lianjie → 顶部标签栏最右「**管理**」

**③ 左侧菜单「仓库成员管理」→ 右上角「添加仓库成员」**

- 输入队友用户名
- 权限选「**开发者**」（别给管理员，管理员能删仓库）
- 确定

**④ 队友接受邀请**

Gitee 会发站内信和邮件，他点开接受后才生效。

> ⚠️ Gitee 个人版限制：**账号下所有私有仓库协作人数合计 ≤ 5 人**。
> 超了以后所有私有仓库会变成只读。

## 1.2 队友操作

```bash
# 1. 拉代码
git clone https://gitee.com/man-qianyi/lianjie.git
cd lianjie

# 2. 自测环境（应该输出「全部通过」）
node app/test.js

# 3. 跑起来
# 微信开发者工具 → 导入项目 → 目录选 lianjie\app
# → AppID 选「测试号」→ 编译
```

> 如果 Gitee 开了两步验证，HTTPS 拉取要用「私人令牌」当密码：
> https://gitee.com/profile/personal_access_tokens

## 1.3 验证权限通了

别等写完代码才发现没权限。先做一次最小验证：

```bash
cd lianjie
echo "" >> README.md
git add README.md
git commit -m "chore: 测试推送权限"
git push origin main
```

**能推上去 = 权限通了。**

# 二、GitHub 版

## 2.1 管理员操作（满谦益）

**① 拿到队友的 GitHub 用户名**

对方没账号先注册：https://github.com/signup

**② 进仓库设置**

https://github.com/yi199/lianjie/settings

**③ 左侧栏 Access 分组 →「Collaborators and teams」**

**④ 点「Add people」**

- 输入 GitHub 用户名（或邮箱）
- 角色选「**Write**」
- 点确认

**⑤ 队友接受邀请**

会收到邮件，点邮件里的链接接受才生效。也可以在这个页面看 https://github.com/yi199/lianjie/invitations

> GitHub Free 的私有仓库**协作者人数不限**，不用担心人数。

## 2.2 队友操作（注意认证方式）

GitHub 私有仓库**不能用账号密码** clone，必须用 SSH key 或 Personal Access Token。

### 方式 A：SSH（推荐，配一次永久有效）

```bash
# 1. 生成密钥（一路回车）
ssh-keygen -t ed25519 -C "你的邮箱"

# 2. 查看公钥，复制输出的全部内容
cat ~/.ssh/id_ed25519.pub

# 3. 粘到 https://github.com/settings/keys
#    → New SSH key → Title 随便填 → Key 粘贴 → Add SSH key

# 4. 测试
ssh -T git@github.com
# 出现 "Hi 你的用户名! You've successfully authenticated" 就是成功

# 5. 拉代码
git clone git@github.com:yi199/lianjie.git
```

### 方式 B：HTTPS + 令牌

```bash
# 1. 去 https://github.com/settings/tokens 生成 classic token
#    勾选 repo 权限

# 2. 拉代码时用令牌当密码
git clone https://github.com/yi199/lianjie.git
# 提示输密码时粘贴令牌，不是账号密码
```

### 然后

```bash
cd lianjie
node app/test.js          # 应该输出「全部通过」
```

微信开发者工具 → 导入项目 → 选 `lianjie\app` → AppID 选「测试号」。

## 2.3 国内网络提醒

直连 github.com 常常很慢或不通。如果 clone 卡住：

- 本机已验证可行：**SSH 走 443 端口**
  在 `~/.ssh/config` 里加：
  ```
  Host github.com
    HostName ssh.github.com
    Port 443
    User git
  ```
- 或者用镜像/加速器

# 三、两边都有权限时，怎么不打架

**只认一个主仓库，另一个当镜像。**

建议：**Gitee 为主**（国内快、队友 pull/push 不卡），GitHub 用于展示和备份。

日常开发只在主仓库上操作，别两边各推各的——否则同一个提交在两个平台会产生不同 hash，同步起来很麻烦。

需要同步时由一个人统一推：

```bash
git push gitee main && git push github main
```

# 四、常见问题

**Q：git 权限有了，为什么真机预览还是不行？**
A：那是两套权限。真机预览/上传代码要去小程序后台加：
`mp.weixin.qq.com → 管理 → 成员管理 → 项目成员`
（本项目现在用测试号，暂时不需要）

**Q：`project.private.config.json` 冲突了怎么办？**
A：这个文件每人的都不一样，已经在 `.gitignore` 里排除了。如果你本地有，**删掉，不要提交**。

**Q：我把 main 搞坏了怎么办？**
A：`git revert` 或找管理员。**不要用 `git push -f`**。

**Q：能直接改 main 吗？**
A：目前可以（没开保护分支）。但请遵守：**改超过 1 个文件、或者动 `utils/` 的，开分支**。推之前先 `git pull --rebase origin main`，再跑 `node app/test.js`。
