## 0. 一句话定位

**一本会记账的训练手册。**

用户在这里拿到计划、一组一组练完并记下重量次数，系统把数据积累成看得见的进步。
手册可以买，数据是自己的。

**它不是什么**（防止越做越像别人）：
- 不是 Keep（不做视频课程库、不做社区内容流）
- 不是薄荷（不做食物热量数据库，只做「吃什么」的清单级建议）
- 不是杯间餐时（它卖内容、你留存数据；它的首页是 slogan，你的首页必须是今天的训练）

## 1. 三条设计原则

> 加功能时先过这三条，过不了的就不做。

1. **每一次打开都要有「下一步动作」**
   首页永远回答「我今天练什么」，而不是展示内容。任何新功能如果不能在 3 秒内让人知道该干什么，放二级页。

2. **用户产生的数据必须留下来，并且能看见**
   训练记录、体重、连续天数——这些是用户离不开的原因。**只存本地的功能（草稿、自建计划）要明确标注，别让用户误以为上云了。**

3. **内容（手册）是变现手段，不是核心体验**
   手册只在「用户已经练起来之后」才有付费意愿。所以顺序是：先免费能练 → 有记录 → 再卖进阶手册。

## 2. 信息架构

```
底部 4 Tab
├── 训练 home        今日训练卡 / 数据条 / 本周出勤 / 动态一行
├── 进度 progress    月历热力图 / 训练容量 / 部位占比 / 体重曲线
├── 手册 shelf       我的计划 · 手册市场 · 自建计划
└── 我的 me          身体数据 / 器材 / 饮食 / 提醒 / 导出

页内跳转（无 tab）
├── 训练执行 train        组次记录 + 休息计时（从首页「开始训练」进入）
├── 动作库 library        动作图鉴 + PR（从 me / 训练页进入）
├── 手册介绍（弹层）      一次买断 / 兑换码 / 一起团购
└── 购买方式（弹层）      单买 / 3 人团 / 6 人团

待建（P2 以后）
├── 训练完成总结页        本次容量 / PR / 分享卡
├── 拼团详情页            成团进度 / 邀请
├── 身体数据详情页        体重·体脂·围度历史
└── 自建计划编辑器        从动作组合一套训练
```

**职责边界**（避免以后功能乱塞）：
- `home` 只做「今天练什么 + 概览数字」，不放图表
- `progress` 只放**过去的数据**，不放操作入口（除了导出）
- `shelf` 只做**计划的选择与管理**，不做训练执行
- `train` 只做**一次训练的执行与记录**，训练结束必须回到 home
- `me` 只做**设置与个人数据**

## 6. 关键业务规则（改代码前必读）

| 规则 | 定义 | 落在哪里 |
|---|---|---|
| **训练容量** | `Σ(weight × reps)` 所有已完成的组；`mode=time` 的组按 `duration × 系数` 计 | 训练结束与进度页共用同一函数 `calcVolume()` |
| **PR 判定** | 三种：最大单组重量、最大单组次数、单动作单次训练容量。任一破纪录 → `is_pr = true` | 写入 `workout_set` 时算，不要事后补 |
| **训练日** | 当天有任意一组 `is_done = true` 即算 | 热力图、连续天数共用 |
| **连续天数** | 从今天往前推，直到遇到没有训练记录的一天 | 别用「自然周」，用户会断签焦虑 |
| **周目标** | 默认 4 次，可在 me 修改 | 首页圆环 = 已完成/目标 |
| **器材过滤** | 动作可用 ⟺ `exercise_gear ⊆ user_gear`（空集恒可用） | 首页推荐与训练页都要过这层 |
| **休息时长** | 默认 90s；`exercise.default_rest` 可覆盖 | 完成一组时读动作配置 |
| **游客态** | 首版不做。直接要求登录后使用（分析里那个「未登录/登录两套界面」是杯间餐时的营销手法，开发量翻倍，不值得） | — |

## 9. 怎么往里加东西（扩展指南）

### 加一个页面
1. 建 `miniprogram/pages/xxx/` 下的四件套（js/wxml/wxss/json）
2. `app.json` 的 `pages` 数组注册
3. 若进 tabBar → 同时改 `tabBar.list`（**注意：tab 最好长期保持 4 个**，加第 5 个会挤）
4. 回到本文件第 3 节登记

### 加一张表
1. 云开发控制台建集合
2. 配权限（用户表只能读自己）
3. 本文件第 5 节登记字段
4. 若涉及统计 → 检查第 6 节的规则要不要同步改

### 加一种动作类型（比如「有氧 30 分钟」）
1. `exercise.mode` 增加枚举值 `cardio`
2. `components/set-row/` 里加一个分支（不显示重量，只显示时长/距离）
3. `calcVolume()` 加对应算法
4. `workout_set` 加 `distance` 字段

### 加一个数据指标（比如「1RM 估算」）
1. `utils/volume.js` 加纯函数
2. `progress` 页加一张 `card-s` 卡
3. 不需要改表（现算）

### 加一个付费功能
1. 先确认虚拟支付的当前政策（**iOS 端有限制**）
2. `plan` 加 `price_*` 字段
3. `purchase` 记权益，前端统一用 `checkAccess(planId)` 判断
4. 不要在页面里散落 `if (paid)` 判断

## 11. 爽点与动效规范

> 这一章解决一个问题：**用户为什么会想再打开一次。**
> 结论先说：健身的爽点是「累积」，不是「推进」——所以不能照搬调酒类产品「一步步完成」的动画结构。

### 11.0 为什么不能照搬「过程同步动画」

| | 调酒（杯间餐时那类） | 健身（本项目） |
|---|---|---|
| 动作结构 | 13 个不同步骤，单向推进 | 12 次 × 4 组，循环重复 |
| 时长 | 3–5 分钟，有终点 | 45 分钟，看不到头 |
| 用户状态 | 手在忙、眼睛有空 | 在使劲、在喘、在数还剩几次 |
| 爽点关键词 | **推进**（看它一步步完成） | **累积**（看它一点点变多） |

**最重要的一条**：训练中（一组之内）**不要做任何动画**。用户在用力，任何动效都是干扰。
全流程只有两个窗口适合放动效：**组间休息的 90 秒** 和 **训练结束那一刻**。

### 11.1 四层爽点

| 层 | 时机 | 时长 | 机制 | 数据依赖 |
|---|---|---|---|---|
| ① 组内 | 一组 20–40 秒 | — | 不做动画，只有次数与呼吸 | — |
| ② 组后 | 完成一组瞬间 | 420ms | 杠铃片逐片点亮 + 容量数字上涨 | `set.weight` `set.reps` `set.is_pr` |
| ③ 组间 | 90 秒休息 | 90s 循环 | 呼吸环：倒计时环 + 光圈随呼吸缩放 | `exercise.default_rest` |
| ④ 训练后 | 结束那一刻 | 3–5s 观感 | 今日战报：容量大数字 + 对比换算 + PR | `workout.volume` |
| ⑤ 长期 | 每周 / 每月 | 1.1s 入场 | 力量地形：容量折线成山 + 部位占比 | `workout.volume` 按月聚合 |

### 11.2 逐层规范

#### ① 组内 · 什么都不做

- 显示：组号、目标次数、上一次同组数据（灰字）
- **禁止**：进度条跳动、数字滚动、庆祝弹窗
- 原因：用户在蹲一半，任何视觉变化都会让他分心甚至受伤

#### ② 组后 · 杠铃点亮（核心，已验证）

**设计修正记录（2026-10-28）**：
最初做的是「每完成一组，杠铃加一片」——物理上不成立。同一动作 4 组重量相同，片数不会变。
**改为**：片数代表**重量**（恒定），颜色代表**进度**（逐片点亮）。这样既真实，又有「这根杠铃被我练熟了」的累积感。

| 参数 | 值 |
|---|---|
| 片数 | `weight ÷ plate_kg`，上限 4 片（24kg ÷ 6 = 4 片） |
| 片尺寸 | 宽 11px、高 46px、圆角 2.5px，片间距 3px，从套筒向外排 |
| 未完成色 | `#D5D2C2` |
| 已完成色 | `#3C4A32` 墨绿 |
| PR 那片 | `#B4795A` 陶土色（仅该组是 PR 时） |
| 点亮顺序 | 从内侧向外（`i = 0` 最靠近套筒） |
| 单次脉冲 | `scale .86 → 1.05 → 1`，420ms，`cubic-bezier(.2,1.4,.4,1)` |
| 容量数字 | 每完成一组累加 `weight × reps`，无滚动动画，直接切换 |
| 4 组全亮 | 整根杠铃进入墨绿「熟」状态（可选：一次 600ms 的柔光） |

- 数字**不跳动**（重量没变），只有一次 260ms 的 `scale 1.08` 脉冲表示「这组记上了」

#### ③ 组间 · 呼吸环

| 参数 | 值 |
|---|---|
| 时长 | 取 `exercise.default_rest`，默认 90s |
| 外环 | 半径 96，`stroke-dasharray = 603`，`dashoffset` 由 0 → 603 线性递减 |
| 内圈呼吸 | `scale .82 → 1.06 → .82`，**9s 一个周期**（吸 4s、呼 5s） |
| 文字 | 0–3s「吸气」，4–8s「呼气」 |
| 提示 | 「跟着圆圈：放大吸气，缩小呼气」 |
| 跳过 | 文字链，不是按钮（避免误触） |
| 背景 | 米白 `rgba(242,240,230,.985)` + `blur(6px)`，盖住下面的内容 |

为什么值得做：组间呼吸引导**是真的有用**（加快恢复、降心率），不是纯装饰。这是全产品唯一能放长动画又不必心虚的地方。

#### ④ 训练后 · 今日战报

| 元素 | 规范 |
|---|---|
| 主数字 | 本次容量，单位「吨」，Georgia 62px |
| 对比 | 「比上次多 XXX kg」+ 一句具象换算（如「差不多是两台冰箱的重量」） |
| PR 卡 | 只显示今天破纪录的那一项 |
| 明细 | 动作数·组数 / 时长 / 连续天数 / 本周完成 |
| CTA | 「看看我的地形 →」引导到长期层 |

**换算库**（把 kg 变成可感知的东西，这是「爽」的关键）：洗衣机 ≈ 60kg、冰箱 ≈ 120kg、行李箱 ≈ 20kg、桶装水 ≈ 19kg。

#### ⑤ 长期 · 力量地形

| 参数 | 值 |
|---|---|
| 横轴 | 最近 12 周（数据点每周一个） |
| 纵轴 | 周训练容量，归一化到 0–1 |
| 形态 | 折线 + 深墨绿渐变填充到基线（`#3C4A32` 78% → 8%） |
| 最新点 | 陶土色圆点标记 |
| 部位占比 | 5 条横条，1.1s `cubic-bezier(.2,.8,.3,1)` 展开，每条延迟 90ms |
| 结语 | 用一句话指出偏科：「腿和胸堆出了主峰，肩还是一条浅浅的坡」 |

**为什么是地形而不是曲线图**：曲线图是「看数据」，地形是「看自己练出来的东西」。它天然适合按月对比，也有收藏欲。

### 11.3 小程序实现方案

> 这是本文档最容易踩坑的地方，先写清楚。

| 元素 | ❌ 不要 | ✅ 应该 |
|---|---|---|
| 杠铃片 | 内联 `<svg>`（**wxml 不支持**） | `<view>` 矩形 + `wx:for`，`background-color` + `border-radius` |
| 片色变化 | `setData` 改内联 style | 用 `class` 切换（`wx:if` / 条件 class），靠 **CSS `transition: background-color .5s`** |
| 呼吸光圈 | canvas 每帧重绘 | **CSS `animation` 作用于 `transform: scale`**（走 GPU，零 setData） |
| 倒计时环 | JS 逐帧算 `dashoffset` 后 `setData` | 两个**半圆遮罩 + `transform: rotate`**（纯 CSS），或基础库 ≥2.9 用 `conic-gradient` |
| 倒计时数字 | 整页 `setData` | 每秒只 `setData({ restNum })` 单字段 |
| 力量地形 | SVG path（不支持） | **`canvas type="2d"`** 绘制路径；或由云函数生成图片存 CDN |

**铁律**：**动画只由 CSS 驱动，`setData` 只负责数据。** 一秒一次的 setData 在长列表里会让页面明显卡顿。

### 11.4 动效红线

1. **组内不放动画**——用户在用力的 20 秒里，任何变化都是干扰
2. **不用 `setData` 驱动动画**
3. **单次动效 ≤ 500ms**（呼吸环除外，它是背景式的）
4. **不做假数据动画**——所有数字必须来自真实记录，宁可数字小也不能编
5. **不做身材变化暗示**——「练 30 天变壮」这类视觉承诺不做，涉及虚假宣传和身材焦虑，也过不了审

### 11.5 验收标准

| 项 | 标准 |
|---|---|
| 完成一组 → 首帧响应 | < 100ms（用户按下到片的颜色开始变） |
| 连续记录 20 组 | 无掉帧、无页面卡顿（开发者工具 Performance 面板查看） |
| 呼吸环后台切回 | 倒计时与实际剩余时间一致，不错乱 |
| 低端机（红米等） | 动画降级：关掉呼吸光圈，只保留外环倒计时 |

### 11.6 本章新增的数据字段

| 表 | 字段 | 用途 |
|---|---|---|
| `exercise` | `plate_kg` | 杠铃片单位重量，用于渲染片数（徒手为空） |
| `workout_set` | `is_pr` | 决定那片是否用陶土色 |
| `workout` | `volume` | 战报大数字与地形纵轴 |
